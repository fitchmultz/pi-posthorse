# Ordering contracts

Posthorse uses Pi's event lifecycle and journal order. It does not sort journal entries by
message timestamps or run a second lifecycle around the host. [Ownership and lifetimes](ownership.md)
identifies the owner of each resource and the contracts for cooperating extensions.

The contract IDs below identify the ordering inventory. Each row names the current implementation
and existing behavioral coverage. A documented host contract is not a request for a second queue,
new event, or extra validation layer.

## History and recovery

Native branch arrays are oldest first, with parents before children. The last matching edit or
receipt in that order is the latest one. Timestamps are display data, not a replacement ordering
key. `HistorySource.branch`, `contextEdits`, `windowProjection`, `NoteEvidence`, and
`recoveryInputs` state this contract where callers supply those arrays.

| Contracts | Current guarantee and owner                                                                                                                                                                                                                           | Behavioral coverage                                                   |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| H1        | Window labels are projected forward through all ancestry metadata before results are reversed or nonmatching content is discarded. Each traversal owns its projection state.                                                                          | Window-label and skipped-archive-entry cases                          |
| H2, R1    | `contextEdits` resolves later edits before recovery selects anchors. `contextStart` chooses the latest boundary before current-input or ancestry selection.                                                                                           | Boundary, edited receipt, and owner-boundary tests                    |
| H3        | An all-session search captures active-context visibility before awaiting archive I/O.                                                                                                                                                                 | Active-context search exclusion cases                                 |
| H4        | Original content ranks before recovery echoes. Assistant block order defines original-text segments. Ranking precedes result and page limits.                                                                                                         | Original-versus-echo ranking cases                                    |
| H5–H6     | Within each rank, branches are newest first; archives use newest file modification time, then newest entries per file. Equal-time files retain discovery order. Each file is scanned forward into a bounded feed and fed backward to the accumulator. | Archive ordering, tied-file, and cross-file cursor cases              |
| H7–H8     | Cursor seeking reaches the anchor before collecting later hits and finishes a partial anchor first. Continuations retain normalized query, scope, qualified ID, text offset, and image offset.                                                        | Partial-header, growing-echo, cross-file, and image cursor cases      |
| H9        | Bare-ID reads check the current branch before archives. Qualified IDs preserve the selected archive identity.                                                                                                                                         | Reused-ID and qualified-history cases                                 |
| H10       | A deferred `SessionLine.text()` is consumed before its iterator closes. Advancing alone does not invalidate it.                                                                                                                                       | Archive reader cases in `test/archive.test.ts`                        |
| R2        | Projected call provenance is established before an `ask_question` receipt can become owner input. Namespaced or unlinked results do not gain authority from their name.                                                                               | Owner-question provenance host cases                                  |
| R3        | Owner anchors use chronological position. Current owner text consumes ancestry space first. Older windows are admitted newest first and rendered oldest first.                                                                                        | Follow-up and superseded-intent cases                                 |
| R4        | `projectedToolEntries` resolves retention against the source before substituting the edit's history-read reference. `recoverableToolResults` receives the resulting boolean.                                                                          | Retained/discarded edited-receipt regression                          |
| R5–R6     | Synchronous evidence is selected relative to the trailing assistant/result region. Async receipts remain eligible after responses. Only projected call links explain receipts; raw omitted calls are not restored.                                    | Trailing result, incomplete response, async, and orphan receipt cases |
| R7        | Required headers and history pointers receive capacity before evidence bodies. Newest evidence is admitted first, then rendered chronologically.                                                                                                      | Minimum-budget and multi-batch recovery cases                         |
| R8–R9     | Tail selection uses Pi's applied projection and materializes projected contributions before the native cut finder. A candidate tail pairs calls before results and includes every call's completion.                                                  | Retention and orphaned-tool host cases                                |
| R10–R11   | Provider-summary cost and the assistant-start rule apply before selecting retained IDs. Recovery is built afterward. Retained spans run from first-kept entry to before the latest compaction in journal order.                                       | Provider-tail and `test/retained-tail.test.ts` cases                  |

History and notes pages read live data. They do not promise snapshot traversal across edits.
Archive readers preserve LF/EOF and decoder state across chunks. Project scoping resolves a
nested session's parent membership before including it. Concurrent enumeration and filtering
preserve discovery order before newest-first search phases. These contracts are covered by the
Unicode archive, project/subagent scope, and tied-file ordering cases.

## Note evidence and storage

| Contracts | Current guarantee and owner                                                                                                                                                                                                                                                                                                                             | Behavioral coverage                                                              |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| E1        | `collectTouches` collects receipts and directories before interpreting calls, then suppresses consumed direct receipts. Legacy call/result journals use Pi's normal call-before-result order.                                                                                                                                                           | Mixed tools, empty scopes, and unknown-cwd recovery cases                        |
| E2        | A recorded effect counts only when its causal root receipt is visible. A delivered completion supersedes the launch, including when the completion is omitted.                                                                                                                                                                                          | Metadata-only and late-background effect host cases                              |
| E3, N15   | Effects retain receipt, call, and path identity. The last verified effect for an owner/call/file supersedes adoption without losing other files in that call. Compatible receipt content preserves full/partial write proof; inferred content cannot mask a verified clear. Effects replay by receipt position and final-effect order within a receipt. | `test/note-evidence.test.ts`; metadata-only host cases                           |
| E4–E5     | Scope interpretation precedes state replay. Reads do not demote written notes. Clears remove notes, partial edits preserve compatible full-write proof, and observed writes require a new read. Primary-note selection follows replay.                                                                                                                  | Ordered note-state and foreign-scope recovery cases                              |
| N1        | `createNotesStore` shares an initializing promise and exposes ready state only after binding and session construction complete.                                                                                                                                                                                                                         | Native session initialization and notes cases                                    |
| N2        | Package notes move before binding and before package cleanup. Existing destination data is preserved; the compatibility link follows migration.                                                                                                                                                                                                         | `test/package-notes.test.ts`; package-update notes cases                         |
| N3        | A session binding survives cwd and tree changes. Binding/seed/candidate replay preserves caller journal precedence, with later matching records winning.                                                                                                                                                                                                | Native navigation, adoption, deletion, and resume cases                          |
| N4–N5     | Snapshot selection uses branch-visible evidence and immediate-parent current bytes. All files and the manifest are complete before directory publication and journal binding. Existing same-owner manifests are recognized on retry; empty scopes publish a manifest on first write.                                                                    | Native selected-branch, missing-source, and fork snapshot cases                  |
| N6        | Snapshot copy checks source identity around exclusive copying, restores times before destination identity capture, and waits for launched work before staging cleanup.                                                                                                                                                                                  | Source-change failure and copied-time cases                                      |
| N7–N8     | The host's same-file queue owns adoption and append together. Note queues precede manifest queues, without recursive same-note acquisition. Append inspects content before choosing a separator and writes one complete record.                                                                                                                         | Concurrent adoption and append cases                                             |
| N9–N10    | Filesystem link traversal precedes dependent `..` normalization. Publication completes content and metadata, restores ownership before mode, closes, checks cancellation, then renames. Cleanup preserves the publication error.                                                                                                                        | Alias/path and failed-publication cases                                          |
| N11       | `SessionNotes.record` normalizes logical paths before updating ownership, revision, or journal metadata. Readers normalize accepted historical aliases. File mutation precedes its success record.                                                                                                                                                      | Native write/append alias, deletion, legacy record, and resume assertions        |
| N12–N13   | An adopted copy gains ownership before a verification/manifest failure is reported; the requested edit does not continue. Own-state lookup precedes inheritance. Ancestors check existing targets and ownership/deletion evidence before following their source, preferring manifests to older binding metadata.                                        | Adoption-failure, deletion, and missing-source cases                             |
| N14       | Note guards capture call ancestry, session, and cwd before execution, prepare adoption, record verified effects at result, and release capture at execution end. Shutdown can precede the final receipt and does not clear the capture.                                                                                                                 | Shutdown-before-receipt and background-branch cases                              |
| N16–N17   | Active edits/omissions apply before touch collection. Own effects precede inherited-scope translation. Address matching tries canonical paths before lexical paths and the longest directory before broader roots.                                                                                                                                      | Edited metadata, foreign-scope, alias, and private-scope cases                   |
| N18       | Parallel note lookups return each address, manifest, or stat together with its input identity. Callers do not zip independent arrays by index. `mapBatch` preserves input order and settles all launched work before propagating failure.                                                                                                               | Fork ownership, discovery, alias, and walk cases                                 |
| N19–N20   | Discovery checks identity/revision before digest reuse and re-stats after hashing. Current-scope representatives precede duplicate collapse, then newest-first paging. Walks check ancestors before recursion and recheck later entries after each subtree. Search batches preserve result order before truncation.                                     | Duplicate/divergence, cycles, disappearing-entry, cancellation, and paging cases |
| N21       | A patch move belongs to the immediately preceding update header. Verified committed paths take precedence over an overall failure flag; previews produce no effects.                                                                                                                                                                                    | Patch-header association and partial-failure receipt regressions                 |

The file queue is not a cross-process transaction. Independent files need no global mutation
order. Touch entries need not follow receipts in journal position. The journal parser can read
non-optimized JSON property order; compact property order only enables its metadata shortcut.
